# AI-work

本目录保存 AI 与开发者协作时产生的工程记录；它不承载 Vivado 工程、RTL、XDC、IP 或工具生成物。

## 当前范围

本次为 Mode 4（新板卡工程初始化与硬件环境）建立以下基础记录：

- `HARDWARE_ENVIRONMENT.md`：唯一的全局硬件事实来源；记录原理图来源、FPGA 资源映射、时钟、配置、GT、JTAG、已确认结论与待确认项。
- `LOG.md`：按时间记录环境建立和每个工作包的计划、执行、验收索引。

本次没有创建、修改或初始化 Vivado 工程，也没有创建 RTL、XDC、IP、bitstream 或网络测试内容。

## 后续开发闭环

当提出一个具体需求后，才创建一个对应的工作包：

```text
AI-work/work-packages/<需求名>-<YYYY-MM-DD>/
  PLAN.md
  EXECUTION.md
  ACCEPTANCE.md
```

工作包遵循固定闭环：

```text
需求 → AI 方案 → 用户确认 → 实现 → 结果与验收 → 用户确认 → 提交/推送
```

`PLAN.md` 必须先从 `HARDWARE_ENVIRONMENT.md` 提取本需求相关的硬件事实；若缺失，只追踪该需求涉及的原理图并先更新总环境文件。计划须经用户确认后才能执行。`EXECUTION.md` 仅记录获批范围内的实际动作和证据。`ACCEPTANCE.md` 对照计划中的验收标准给出结论与限制。

如果某个已批准工作包需要 Vivado 工程，才通过受版本控制的 Tcl 在该工作包方案所确定的位置创建；不预建空工程，也不使用不可复现的 GUI 手工创建流程。

工作包验收结论需要用户接受后，才提交或推送到项目仓库，除非用户对该工作包明确预授权自动提交。
